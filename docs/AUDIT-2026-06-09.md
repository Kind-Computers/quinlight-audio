# Quinlight-Audio Code Audit — 2026-06-09

Full-codebase audit: serious bugs, inconsistencies, edge cases, and design-intent conformance.
Method: nine parallel review passes (registration/rotor, spectral, remaster orchestration,
remaster I/O+caching, cleanup, simd+upsample, player/FFI/HRTF, app layer, design conformance),
followed by direct source verification of every Critical/High finding and most Mediums.
Ground truth: `cargo test --lib` 355 pass, `cargo test --bin` 410 pass, clippy clean except one
style nit (`remaster.rs:2037` manual checked division). No code changes were applied.

Severity legend: **Critical** = core feature produces wrong audio on realistic input.
**High** = silent data corruption or broken invariant on reachable paths. **Medium** = real bug
or edge case likely to matter. **Low** = latent/defensive/doc issues.

## Critical

### C1. `burg_lpc` backward-error lag bug — AR repair emits clamped full-scale garbage on noisy signals
`src/cleanup/shared.rs:616-618` (read) vs `:635-640` (update). Textbook Burg pairs `f_m(t)` with
`b_m(t−1)`; this code writes the updated backward error to index `t−1` and the next stage *also*
reads `eb[t−1]`, so from stage 2 on the cross-correlation pairs `f_m(t)` with `b_m(t)` (off by
one). Forward/backward errors at the same index stay strongly correlated, so reflection
coefficients lock near the ±0.9999 clamp at every stage (empirically ±0.962 × 24 stages on
two-tone + 0.5 % noise) and the predictor diverges (reaching ~1.8e5 from a 0.45-peak context).
`repair_gap_ar` (`shared.rs:536-543`) then clamps to `max(context_peak, 1.0)` → the repaired gap
becomes a ±1.0 rectangular burst, far louder than the click it replaces.

Blast radius: `RepairMode::Ar` is used by DeclickAr (V1+V21), Decrackle (V1+V21), pre-declip
(**every non-Off cleanup mode**, `shared.rs:100-105`), and both retired presets. Cleanup defaults
to **Off** in GUI and CLI, so default runs are unaffected — but the feature is broken whenever
enabled, and corrupted output is baked into the sample cache. Existing tests use noiseless pure
sines, for which any AR fit annihilates the signal regardless of the lag convention — that's why
CI is green.

Fix: store the updated backward error at `t` (textbook indexing / NR-style shifted read from
`t+1`), and add a noisy-signal regression test.

## High

### H1. SAx high-offset rescale overflows `u32` — silent pattern corruption in release, panic in debug
`src/remaster.rs:7218-7221`: `((old_val << 16) * new_r / old_r) >> 16` with `new_r = 48_000`.
`old_val ≥ 2` overflows u32 (2·65536·48000 ≈ 6.3e9 > 4.29e9). Release wraps (e.g. SA2 at 8363 Hz
→ 3 instead of 11 — offset lands 8·65536 samples early); debug builds panic at interactive module
load (`normalize_samples_to_48k` runs this for every loaded S3M/IT). The shift dance is
mathematically `old_val * new_r / old_r` — the shifts exist only to overflow. Additionally SAx
and Oxx are scaled independently with floor, dropping carry between high/low parts (worst-case
error just under 65 536 samples).

### H2. `ENGINE_PIPELINE_VERSION` never reaches the active cache key — documented invalidation contract is dead
`src/remaster.rs:6465-6470` documents bumping the constant to invalidate caches; it feeds only
`compute_engine_cache_key` (`:6665`), used solely for the "very old" legacy `.wav.zst` lookup
(`:6288`). The active path is filename-keyed `Quinlight-{pcm_hex}-{engine}-ddim{n}.flac`
(`cache_flac_path`, `:6085`). Bumping the version invalidates nothing current; the next
conditioning/extraction change ships and stale FLAC entries silently satisfy lookups. A unit test
asserts the version changes the (dead) key, reinforcing the false confidence.

### H3. Loop metadata absent from the active cache key while the cached payload depends on it
The cached artifact is the **post-extraction** candidate (`maybe_finish_engine_job`
`:5962-5970`: `assemble_sample_candidate` → `cache_store`), whose content depends on
`job.loop_info` (tiling layout, body slicing, crossfades). The key is PCM-SHA256 + engine id +
ddim steps only. Same PCM with different loop points (edited loops, differently-ripped modules)
hits the wrong entry: audio extracted under a mismatched tiling, degrading the sample-exact-loop
promise with zero indication. (Even the legacy key omitted the sustain loop —
`spec_loop_fields:6645`.) Fix: fold loop fields (incl. sustain), rates, bit depth, and pipeline
version into the FLAC key.

## Medium

### M1. Loop seam guard misanchored when the master is shorter than the engines *(registration)*
`src/engine/registration.rs:650-663, 736-738`. `apply_seam_master_blend` anchors the tail guard
to `min(out.len(), master.len())`; with `3 ≤ align_n < out_len` the guard lands at interior
samples (100 % master sample injected mid-buffer at `align_n−1`) while the true loop endpoint
`out_len−1` gets no guard and no flow pin. Fires whenever the sinc master is even one frame
shorter than `min_frames` (resampler rounding). The only short-master test uses lengths 0/2,
which skip this region.

### M2. Silent/DC stereo channel caps the engine score at 0.5 — sample can never pass the 0.9 gate
`src/engine/spectral.rs:46-53` averages per-channel scores; `src/simd.rs:73-76` returns 0.0 for
zero variance even when reference *and* candidate match exactly (cross-rate path: `:552-564`).
A stereo sample with one silent channel (common in converted modules) scores ≤ 0.5 forever.
Fail direction is safe (left unremastered), but the score is wrong — a degenerate matching
channel should be neutral, not 0.0. This is a scoring bug, not gate strictness.

### M3. Loop-aware STFT padding silently disabled for loops shorter than one FFT frame
`src/engine/spectral.rs:307`: `looped && signal.len() >= pad` — below one frame (2048 @ 48 kHz
≈ 42.7 ms) looped signals are reflect-padded, defeating the circular-continuity purpose exactly
for short chip loops (a 64-sample loop at 8363 Hz is ~370 samples at 48 kHz). Fix: tile
circularly N times. Loop-continuity tests only use n ≥ fft_size.

### M4. Engine child `wait()` is uncancellable on the normal path; no subprocess timeout exists
`src/remaster.rs:8038-8040` returns from the inotify watcher once all outputs are processed while
the child still runs; `:945` then blocks in `child.wait()` with a single prior cancel check. A
PyTorch teardown hang (acknowledged in comments at `:497-498`) makes Cancel spin forever. The
cancellable `poll_child_until_exit_or_cancel` (`:7903`) is only used on the non-inotify fallback.

### M5. Chunk-stitch crossfade uses equal-power law over *correlated* sources; seam bulge can attenuate the whole file
`src/upsample.rs:177-185`: overlap regions are the same input audio independently AI-rendered
twice (each chunk its own `SampleJob`), i.e. highly correlated — equal-power summing peaks at √2
(+3 dB) mid-fade. `write_upsample_flac_24bit` (`:861-864`) then rescales the **entire file** by
`1/peak`. Equal-gain (linear) fade is the correct law for correlated material. The in-tree test
codifies the √2 bulge rather than catching it.

### M6. `HSA_OVERRIDE_GFX_VERSION=11.0.0` forced on every AMD GPU
`src/engine/mod.rs:433-436` sets it whenever device == "cuda", which covers NVIDIA *and* AMD
(`gpu_device_string`, `:138-144`). On any AMD GPU that isn't RDNA3/gfx1100 (gfx1030, gfx90a,
RDNA4…) ROCm dispatches wrong-arch kernels → every engine run faults → silent per-round CPU
fallback (`remaster.rs:976-996`). Symptom: "GPU never works on AMD" unless it's an RX 7000.
Gate on detected gfx version.

### M7. Ctrl-C mid-remaster exits 1 ("fatal engine failure") instead of a clean cancel
`src/batch.rs:671-677`: the `Ok(outcome)` branch counts `no_output_indices` as FATAL with no
`shutdown_flag` check (the `Err` branch checks at `:711`). Cancellation closes the result channel
early → missing finals → misclassified exit code, breaking the documented 1-vs-2 contract for
scripts.

### M8. User-disabled engines still run on every sample in registered mode
`src/remaster.rs:269-296, 386-447`: unselected engines become `fallback_engines`; registered mode
(the default) dispatches all fallback engines on all samples (wave 2). `--engine lavasr` ("Restrict
... to the selected engine(s)", `main.rs:271-273`) and unchecked GUI engines still load models,
burn GPU, and join the consensus. Deliberate per the code comment, but it contradicts the
user-facing contract and the GUI's per-slot `engines_total`.

### M9. HRTF init parses a 36–72 MB SOFA file inside the audio callback under the player lock
`src/player.rs:478-487`; `hrtf_enabled` defaults true (`:184`), so the first callback blows its
deadline at startup → spurious underrun → buffer growth + device reopen (`check_and_grow_buffer`).
Move init to `Player::new()`/loader thread.

### M10. Offline render stalls the audio callback and falsely triggers buffer growth / device bounce
`src/player.rs:636` (`render_live_to_samples` holds `inner` for seconds on a background task);
callback blocks on the same mutex (`:408`); first callback after release records a giant gap →
underrun flag; `gui/mod.rs:2415` calls `check_and_grow_buffer()` on Tick *before* the
`render_progress_rx` guard at `:2453`. Every export doubles the buffer (ratchets toward 16384
frames ≈ 341 ms, never shrinks) and bounces the device; a concurrent second export can freeze the
GUI thread on `*dev_guard = None` (`:907`, SDL close joins the blocked audio thread).

### M11. `Module::replace_sample_data` is a safe fn that can make C read out of bounds *(latent soundness)*
`src/openmpt.rs:1118-1160`: takes `&[f64]` plus independent `length_frames`/`channels`, never
checks `data.len() >= frames*channels`; the C side reads exactly that many doubles
(`libopenmpt_impl.cpp:2531-2537`). All current callers are consistent; the invariant belongs in
the wrapper (`assert!`/`return false`).

### M12. Ping-pong loop extraction can splice a time-reversed body copy
`src/remaster.rs:8294-8448` scores odd (backward) copies against a reversed template and
`extract_single_channel_output` (`:8612-8658`) slices the winner **without reversing**. When an
odd copy wins, the head→body junction splices forward head into reversed body — a content
discontinuity the 16-frame seam fade can't fix. Restrict selection to even indices for ping-pong
(or reverse the slice).

### M13. Cumulative rounding drift in `tiled_offsets` — tiny chip loops slice from wrong content
`src/remaster.rs:8143-8179`: per-copy increment uses the double-rounded `body48`, error up to
~1 frame/copy; `choose_body_copies` (`:3623`) is uncapped, so a 3-frame loop at 8363 Hz → ~14 000
copies → tail slice lands ~0.23 s past truth. When the loop doesn't extend to the sample end, the
key-off tail is taken from wrong content. Tiny bodies also skip the correlation rescue
(`BEST_COPY_MIN_TEMPLATE_FRAMES = 64`).

### M14. Non-XM offset patching assumes instrument == sample+1 — wrong for instrument-mode IT
`src/remaster.rs:7187`. True for S3M/sample-mode IT only. Instrument-mode IT (common): rows for
the remastered sample go unpatched (offset ~6× early after 8363→48k) and rows of a different
sample sharing the instrument number get wrongly scaled. The XM path resolves correctly via
`instrument_sample_for_note` (`:7260-7264`); the non-XM path should too. Runs at every load.

### M15. `extract_single_channel_output` debug assert fires on legitimate modules
`src/remaster.rs:8638-8646`: two-step rounding can give `head48 + body48 > trim` for a tiny head
plus loop-to-end (e.g. head_n=1, body_n=10 @ 8363→24000: 6+58 > 63). Debug builds panic on a
normal chip-sample shape; release emits a channel one frame long (mono keeps it).

### M16. AR/median repair clamp floor of 1.0 permits +26 dB repairs in quiet samples
`src/cleanup/shared.rs:536, 575`: `clamp_bound = max(context_peak, 1.0)` — for a 0.05-peak
context a divergent extrapolation may hit digital full scale. Bound should be context peak (+
small headroom). Compounds C1; independent of it.

### M17. `detect_clip_mask` plateau chunking flags tails of legitimate full-scale square waves
`src/cleanup/shared.rs:261-278`: oversized plateaus are consumed in `max_region+1` chunks and the
final remainder chunk passes both gates (genuine plateau-end edge, zero span) — last samples of
every plateau get "repaired", pitch-dependently (17-sample plateau → flagged; 16 → not). Skip to
the true plateau end instead of re-entering. Pre-declip runs for every active mode, so this feeds
C1's repair path on chip-style square/pulse samples.

### M18. Production f64 SIMD kernels have zero scalar-parity tests; benches cover the dead f32 set
`src/simd.rs:1393-1618` parity-tests only the unused f32 kernels (+pearson); `rms_f64`,
`peak_abs_f64`, `add/subtract_in_place_f64`, de/interleave f64 — the kernels production calls —
have no direct tests; `benches/simd_kernels.rs` likewise benchmarks the f32 set.

### M19. Batch render fatal double-counts and doesn't stop the batch
`src/batch.rs:756-766`: render `Err` increments `fatal_count` and `break`s only the format loop;
`succeeded += 1` still runs; batch continues to next files (a remaster FATAL stops it). Exit code
ends up 1 (correct), but the summary lies and "fatal = stop" is inconsistent.

### M20. Two-wave CLI redispatch computes the full consensus twice per sample
`src/remaster.rs:285-288` claims Final fires once per sample in CLI mode; with fallback engines
present wave 1 emits a Final before totals are bumped, wave 2 emits a second — consumers dedupe
correctly (verified), but the expensive `build_quinlight_result` (LK consensus + loop search)
runs twice for every sample in the default registered mode. Perf + stale doc.

## Low / informational (condensed)

- **registration.rs**: K=1 passthrough skips NaN scrubbing (contract inconsistency); seam blend
  mixes unscrubbed master; `polar_slerp` floor branches yield negative magnitude for t∉[0,1] (no
  current caller does this).
- **spectral.rs**: `softmin_magnitude` is dead code hidden by `#![allow(dead_code)]`; tests named
  `intersection_softmin_*` pin geometric-mean behavior; <4-sample inputs are silenced rather than
  passed through; odd-FFT Hermitian break in `apply_source_frequency_blend` (unreachable at 48 kHz);
  NaN polarity differs between the two "kept in sync" gate predicates (`remaster.rs:5153` fail-closed
  vs `:1066` fail-open).
- **remaster.rs**: cache tmp name lacks PID (cross-process collision → detected miss, wasted work);
  f64-bit hashing is endian-local (fine for local cache); `pad_for_engine` degenerate-loop `resize`
  can truncate >5.12 s samples (needs corrupt loop meta); legacy `.wav.zst` header `debug_assert`;
  cache stores clipped copy (±1.0); `maybe_finish_engine_job` errors discarded (`let _ =`,
  `:8012,8088`) — real cause of "no output" lost; `kill_child_best_effort` kills only the immediate
  child (Python grandchildren orphaned; no setsid/killpg); `bump_all_samples_for_full_dispatch`
  silently skips jobs without wave-1 entries (latent: becomes silent data loss if any engine ever
  overrides `supports_original_rate`); a failing *user-disabled* fallback engine aborts the whole
  run (`:1022-1031`).
- **player/hrtf**: volume fade steps per interleaved sample (fade 2× fast, L/R one step apart);
  HRTF wet path acquires permanent zero-stuffed delay for non-256-multiple SDL buffers (~5 ms comb
  at 33 % mix; power-of-two defaults immune); `process_block` error path desyncs L/R and can
  eventually panic in the callback (practically unreachable with sofar 0.3.0); SOFA failure only
  `eprintln!`s — GUI checkbox stays checked while playback is dry; module load doesn't clear
  keyjazz voices or drain queued commands; `current_playback_rate` stores requested, not
  negotiated, rate; `Module` struct doc says "Not Send" while a justified `unsafe impl Send`
  exists at `openmpt.rs:1471` (doc stale); HRTF peak limiter never releases (all-time max env).
- **app layer**: `probe-metadata` drops sample/instrument name 0 (1-based loop over 0-based API,
  `main.rs:1300-1308`); `convert --sample-rate 192000 --format m4a` writes 96 kHz content in a
  "...192Khz.m4a" filename; GUI default export name always says "Quinlight-Audio-Remastered" even
  for never-remastered modules (labeling integrity); failed render export sets
  `RemasterStatus::Failed` and orphans a live remaster worker (`gui/mod.rs:5043-5046`); AudioSR
  wrapper lacks per-item `except` (one bad item aborts the whole chunk → full CPU re-run) and has
  a latent `torch.functional.pad` AttributeError (`audiosr.rs:119`); archive entry *listing* is
  unbounded before the candidate cap; engine/GPU detection has no timeout and blocks first paint
  (wedged `nvidia-smi`/venv import hangs the window); `replaced` vs `consensus_replaced` counters
  are always equal (vacuous distinction); ddim_steps invalidates caches of engines that ignore it;
  cancellation between modules exits 0 (indistinguishable from completion).
- **cleanup**: retired-preset hash tags alias active V1 tags (harmless today — data-in-hash saves
  it — but fix the tag values); odd-length interleaved buffers change output length inconsistently
  by mode.
- **simd/upsample**: `scale_to_i24le_bytes` wraps (polarity-inverts) out-of-range samples instead
  of clamping (dead code today, but it's the benchmarked kernel); `pearson_correlation` differs
  ~1e-10 across ISA dispatch (FMA + reduction order) — a score exactly at the 0.9 boundary is
  machine-dependent (measure-zero; worth a comment); `rms_f32` SIMD accumulates in f32 vs scalar
  f64 (dead code); `tmp_path_for` collision/litter across concurrent invocations; floor-vs-engine
  length off-by-one between single- and multi-chunk paths.

## Verified-correct highlights (load-bearing claims that check out)

Registration pyramid ×2 flow scaling, cumulative ±2 clamp before warp, R²-gate algebra,
reducer math (median/mean/winsorized MAD), master-in-median-only; STFT round-trip normalization
and Nyquist fenceposts; FFmpeg unsafe copy length math and `set_len` discipline; `resample_audio`
tail drain and `scaled_loop_region` monotone rounding; Oxx ×256-domain rescale (modulo H1's SAx
sibling); archive bounds (limit checked before write, in-memory only); render temp+rename
atomicity, true-peak-bounded single-gain "limiter", AAC resample-not-fail; exit-code ordering
(Fatal > QualityGate, modulo M7); per-subprocess env isolation; `replace_sample_data` C-side copy
semantics; Module Send-not-Sync discipline under the player mutex; playback-vs-export stereo
separation consistency (33 %); SIMD tail handling and quantizer saturation/NaN-to-zero;
double-precision build flag verified load-bearing in the fork.
